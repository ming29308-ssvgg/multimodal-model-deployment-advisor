# 多模态模型部署选择 Agent 设计

## 意图

构建一个可以在当前 Windows 电脑直接运行、也能扩展到工作站、服务器和 Kubernetes 环境的 LangGraph Demo。用户只输入自然语言任务，系统自动检测部署环境，并推荐适合该任务和硬件的模型、推理框架与部署策略。

## 目标

- 自动检测操作系统、CPU、内存、磁盘、GPU、显存、驱动和已安装运行时。
- 理解文本、图片、音频、视频及组合任务，并拆解为模型能力流水线。
- 依据任务能力、硬件资源、系统兼容性和运行时兼容性对模型排序。
- 输出首选、备选模型，以及量化、CPU Offload、分阶段加载或远端服务器建议。
- 提供 FastAPI 接口、命令行入口和离线测试。
- 第一版不下载、不启动任何大型模型，也不依赖外部模型 API。

## 非目标

- 第一版不创建 Kubernetes Deployment。
- 第一版不执行真实模型推理或基准测试。
- 第一版不实现完整 GPU 集群调度器。
- 第一版不承诺模型目录实时覆盖全部新模型。

## 约束

- Python 3.12。
- LangGraph 1.x，使用 `StateGraph`、显式节点和条件边。
- 必须在当前 Windows 11、RTX 4060 Laptop 8GB、16GB RAM 环境运行。
- NVIDIA 检测优先使用 `nvidia-smi`；检测失败时必须降级而不是崩溃。
- 用户不填写硬件数据，只提供任务和可选偏好。
- 模型信息存放在本地 JSON，便于后续独立更新。

## 方案比较

### 直接包装现有硬件推荐工具

开发快，但被第三方 CLI、模型目录和平台兼容性绑定，不利于表达课程中的 LangGraph 分层。

### 自包含检测和推荐引擎

实现本地探测、任务分类、资源估算和模型评分，最适合可运行 Demo。首版采用该方案。

### 完整服务器与集群调度平台

能力最完整，但超出首版范围。通过探测器和部署策略接口为后续接入 GPUStack、Kubernetes Node Feature Discovery 等组件预留扩展点。

## 工作流

1. `classify_task`：解析自然语言任务，得到模态、能力和流水线阶段。
2. `detect_environment`：自动收集当前节点硬件和运行时。
3. `route_environment`：根据个人电脑、服务器或集群进入对应分析节点。
4. `select_models`：从本地模型目录筛选并评分。
5. `build_plan`：生成模型组合、部署方式、命令提示、风险和兜底建议。

## 评分原则

- 任务能力覆盖是硬门槛。
- 系统和运行时不兼容的候选不能成为本地首选。
- 显存估算包含模型基础需求和安全余量；同时参考总显存和当前可用显存。
- 系统内存不足时降低评分或判定不支持。
- 复杂任务按阶段分别推荐模型，避免要求单一模型覆盖所有能力。
- 输出 `ideal`、`runnable`、`constrained`、`unsupported` 四类适配等级。
- 推荐结果标注检测来源与估算性质，避免把估算描述成实测性能。

## API

`POST /api/v1/model-selector/recommend`

请求只包含：

```json
{
  "task": "把会议视频转成文字，区分说话人，然后生成中文摘要",
  "preferences": {
    "quality": "balanced",
    "max_candidates_per_stage": 3
  }
}
```

响应包含任务分析、自动检测的环境、各流水线阶段候选模型、部署计划和警告。
